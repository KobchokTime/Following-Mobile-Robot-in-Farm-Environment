# Thesis Desk

เกมเดสก์ท็อปสำหรับวิทยานิพนธ์ **Following Mobile Robot in Farm Environment** มีต้นแบบ 3D low-poly ที่สร้างด้วย Godot และแอป tracker Tkinter รุ่นเดิม ข้อมูล quest อ่านจากไฟล์ในเครื่อง ไม่มี API หรือบริการคิดเงิน

## เล่นเกม 3D (ตัวหลัก)

ดับเบิลคลิก `run_3d_game.bat` เกมจะเปิดเป็นแอปบนเครื่อง ใช้ WASD/ลูกศรเดิน, E โต้ตอบ, ESC เปิด/ปิด Quest Journal และปุ่มด้านบนเปลี่ยนระหว่าง Office กับ Test Field สนามทดลองเป็นผังโล่งมีแปลงผัก 4 แปลงและทางเดิน/จุดตัดสินใจสำหรับเลือกวิ่งตรงหรือเลี้ยว เดินเข้าใกล้ NPC เพื่อคุย หรือสถานีเพื่อเลือก Robot Run, Tracking, Camera Test และ Motor Test ผลทั้งหมดเป็น simulation และไม่ส่งคำสั่งไปยังฮาร์ดแวร์

Godot 4.7.2 แบบ portable อยู่ใน `.tools/godot/` (ไม่รวมใน git); ตัวเกมอ่าน Main Quest จาก `thesis_data.json` และเก็บตำแหน่ง, XP จำลอง และประวัติรอบไว้ใน `user://thesis_quest_save.json`

## Tracker รุ่นเดิม

ดับเบิลคลิก `run_thesis_tracker.bat` เพื่อเปิดแอป Tkinter สำหรับแก้รายละเอียด quest

แท็บ **HERO / ROBOT** มีตัวละครนักวิจัยพร้อมเลเวลและ XP (เควสหลักให้ 100 XP, เควสเสริม 30 XP; ทุก 100 XP เลื่อนหนึ่งเลเวล) และหุ่น companion ที่เปลี่ยนชื่อ/เลือกอุปกรณ์ติดตั้งได้ อุปกรณ์จะปลดล็อกจากเควสที่เกี่ยวข้อง ข้อมูลเลเวลและ loadout เก็บในเครื่อง; ภาพหุ่นและโหลดเอาต์เป็นส่วนของเกม ไม่เชื่อมต่อหรือส่งคำสั่งไปยังฮาร์ดแวร์จริง

## เปิดแอพ

ดับเบิลคลิก `run_thesis_tracker.bat` หรือเปิด PowerShell ในโฟลเดอร์นี้แล้วรัน:

```powershell
py -3 app.py
```

ต้องมี Python 3 ที่ติดตั้ง Tkinter มาด้วย

## ใช้งาน

- **Main Quest** คือเส้นเรื่องหลักของ thesis เรียงตามเงื่อนไขการทดลอง เมื่อทำด่านก่อนหน้าเสร็จ ด่านถัดไปจึงปลดล็อก
- **Side Quest** คืองานสนับสนุน/เครื่องมือเสริม ทำเมื่อสะดวกและไม่บล็อก Main Quest
- เลือก Main Quest, Side Quest หรือหมวดงานจากแถบซ้าย/ตัวกรองด้านบน
- เลือกงานเพื่อแก้ไขสถานะ ความสำคัญ กำหนดส่ง และบันทึกย่อ
- เพิ่มเควสใหม่ด้วยปุ่ม **เพิ่มงาน** แล้วเลือกว่าเป็น Main Quest หรือ Side Quest
- ข้อมูลทั้งหมดเก็บใน `thesis_data.json` ในโฟลเดอร์โปรเจกต์นี้

## เส้นทาง Main Quest

1. เก็บผล orientation ซ้ำหลายสภาพและประเมินตามเกณฑ์
2. บันทึกการทดสอบ target loss และ reacquisition
3. เก็บ identity ground truth จากสถานการณ์จริง
4. เปรียบเทียบ baseline การติดตามและประเมิน wrong-follow/ID switch
5. ทำ conference experiment อย่างน้อย 10 scenarios พร้อมหลักฐานครบ
6. วิเคราะห์ metrics ที่ย้อนกลับไปยัง raw data ได้
7. เขียนวิทยานิพนธ์จากผลที่ตรวจสอบได้ พร้อมข้อจำกัด

งานตั้งต้นบันทึกไว้ว่าระบบ detector, pose service, protocol/evaluator และการตรวจ hardware แบบ read-only ทำแล้วตามหลักฐานที่มี เควส LiDAR พักไว้จนกว่าจะยืนยันว่ามีอุปกรณ์

รายการงานตั้งต้นสรุปจากเอกสารและบันทึกการทดลองของโครงการวิจัย สถานะและบันทึกอ้างอิงอยู่ในรายละเอียดของแต่ละงาน; วันที่ส่งยังเว้นว่างเพราะเอกสารต้นทางไม่ได้ระบุไว้

แอพใช้บันทึกเควสและโหลดเอาต์ในเครื่อง ไม่เชื่อมต่อหรือส่งคำสั่งไปยังหุ่นยนต์
